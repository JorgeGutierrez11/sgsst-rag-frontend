# OpenCode Notes

## Project shape
- Single Next.js app at the repository root; `pnpm-workspace.yaml` only holds pnpm settings (`allowBuilds`, `minimumReleaseAgeExclude`), there are no workspace packages.
- App Router: `app/layout.tsx` is the root layout; the `app/(main)` route group wraps `/`, `/consulta`, and `/diagnostico` in `components/layout/app-shell.tsx`.
- `components/layout/app-shell.tsx` is the client shell for the Spanish NormIA UI; update visible copy in Spanish unless the product requirement says otherwise.
- Shared UI primitives live under `components/ui`; aliases come from `components.json` and `tsconfig.json` (`@/*`, `@/components`, `@/lib`, `@/components/ui`).

## Backend access
- The browser never calls the backend directly. API clients (`features/*/api/*.ts`) use relative `/api/v1/*` URLs and the shared `shared/api/http-client.ts`.
- `proxy.ts` (Next 16 proxy, matcher `/api/v1/:path*`) rewrites those requests to `SGSST_API_URL`, read at runtime on every request. It answers 503 when the variable is missing or invalid and 404 for paths outside `/api/v1/`.
- Never reintroduce `NEXT_PUBLIC_*` backend URLs or absolute backend URLs in client code: they would be inlined at build time and bypass the proxy.
- `app/api/health/route.ts` is the container health endpoint and does not depend on the backend.
- See `.env.example` for the `SGSST_API_URL` value per mode (`pnpm dev` vs Docker).

## Toolchain and commands
- pnpm 11.25.0 is pinned via `packageManager` and Node 24 via `.nvmrc`; pnpm is the only package manager (`pnpm-lock.yaml`).
- Scripts in `package.json`:
  - `pnpm dev` — run the Next.js dev server.
  - `pnpm build` — run `next build` (standalone output).
  - `pnpm start` — run the production server after a build.
  - `pnpm typecheck` — `tsc --noEmit`.
  - `pnpm lint` — ESLint 9 with `eslint-config-next` (ESLint 10 breaks `eslint-plugin-react`).
  - `pnpm test` — Vitest unit tests (`**/*.test.ts`, node environment).
- No formatter script is defined.

## Build/type gotchas
- TypeScript errors fail `pnpm build`; `ignoreBuildErrors` was removed.
- `experimental.proxyTimeout` is 120s for slow RAG answers; it is fixed at build time, unlike `SGSST_API_URL`.
- `next-env.d.ts` is regenerated by `next dev`/`next build` and flips between `.next/dev/types` and `.next/types`; do not commit that churn.
- Images are configured with `images.unoptimized: true`; do not assume Next image optimization is active.

## Docker and CI
- `Dockerfile` mirrors the backend layout (numbered sections); targets: `development` (next dev) and `runtime` (standalone server as the `node` user with a `/api/health` HEALTHCHECK).
- Compose mirrors the backend: `compose.yaml` builds `sg-sst-frontend:local` and requires `SGSST_API_URL`; `compose.dev.yaml` adds hot reload with read-only source mounts; `compose.backend-network.yaml` joins the backend network `sg-sst_default` (`SGSST_API_URL=http://backend:8000`).
- GitHub Actions: `.github/workflows/tests.yml` (typecheck, lint, test, build; also reusable via `workflow_call`) and `image.yml` (runs `tests.yml` first, then image build, hygiene, startup smoke test). On pushes to `main` only, `image.yml` re-tags the smoke-tested image (never rebuilds) and pushes `ghcr.io/<owner>/sg-sst-frontend:sha-<7>` and `:main` with `GITHUB_TOKEN`; pull requests never push. Nothing deploys; the production compose lives in the backend repo (`deploy/`).
- The `tests.yml` concurrency group carries a `-tests-` suffix because, when called, `github.workflow` is the caller's name; an identical group would deadlock.
- Usage details for humans live in `GUIA_EJECUCION_FRONTEND.md`.

## Styling/UI conventions
- Tailwind CSS v4 is wired through `postcss.config.mjs` with `@tailwindcss/postcss`.
- Global styles and theme tokens are centralized in `app/globals.css`, including `@import 'tailwindcss'`, `tw-animate-css`, and `shadcn/tailwind.css`.
- shadcn config uses `style: "base-nova"`, React Server Components enabled, and Lucide icons.
- `components/ui/button.tsx`, `lib/utils.ts`, and their supporting dependencies are kept as shadcn/base-nova primitives even if the current app does not import them yet.
